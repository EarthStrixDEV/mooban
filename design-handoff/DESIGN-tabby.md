# DESIGN-tabby.md — สเปคส่งมอบ UI ของ Tabby (สมุดจดหนี้เพื่อน)

เอกสารนี้ใช้คู่กับ `Spec: Tabby (SWH Test App)` (Claude Doc id `3b70e9a5-d40d-4820-9823-f9b1afac65da`) และบอร์ดอ้างอิงใน `reference-boards/` (ไฟล์ `.dc.html` เปิดดูเป็นโครง HTML + inline style ได้ แต่ **ไม่ใช่โค้ดที่ต้องคัดลอก** ให้แปลงเป็น class + token ตามเอกสารนี้)

**ลำดับความสำคัญเมื่อขัดกัน:** Spec (API, ข้อมูล, endpoint, ตัวเลขเพดาน) > เอกสารนี้ > บอร์ด ที่ที่บอร์ดขัดกับ spec จะบอกไว้ในหัวข้อ "ช่องว่างและจุดที่ขัดกับ spec" ด้านล่าง

- ข้อมูลในบอร์ดทั้งหมด (ต้น, แพรว, ฿12,345, 48.2 Mbps ฯลฯ) เป็น **sample data** ห้ามฮาร์ดโค้ดลงแอป
- แอปเป็น HTML + CSS + JavaScript ล้วน (fetch API) ไม่มี build step ไฟล์หน้าเว็บชุดเดียวใช้ร่วมกันทั้ง 4 stack (Apache+PHP, Nginx+PHP-FPM, Node/Express, Flask) จึง **ห้ามมี logic ฝั่งหน้าเว็บที่ต่างกันตาม stack**

## 1. ภาพรวมและแผนที่บอร์ด → route

Spec กำหนดหน้าไว้ 2 path เท่านั้น คือ `/` (รายการหนี้) และ `/test` (เครื่องมือทดสอบ) ส่วนหน้าเพิ่ม/แก้ไข/ลบในบอร์ดเป็น **view หรือ dialog ภายใน `/`** ไม่ใช่ path ใหม่ (ใช้ hash route `#/new`, `#/edit/{id}` เพื่อไม่ต้องตั้ง rewrite เพิ่มบน server)

| บอร์ด | route / state | อุปกรณ์ |
|---|---|---|
| `Main.dc.html` | `/` รายการหนี้ ตัวกรอง "ยังไม่จ่าย" + toast เลิกทำ | มือถือ |
| `Tabby-Add.dc.html` | `/#/new` ฟอร์มเพิ่มรายการ (แสดง error ช่องจำนวนเงินเป็นตัวอย่าง) ใช้ฟอร์มเดียวกันกับ `#/edit/{id}` | มือถือ |
| `Tabby-Delete.dc.html` | `/` + bottom sheet ยืนยันลบ (state `dialog open`) | มือถือ |
| `Tabby-Empty.dc.html` | `/` เมื่อ `total = 0` (ทุกตัวกรองว่างแบบ "ทั้งหมด") | มือถือ |
| `Tabby-Test.dc.html` | `/test` | มือถือ |
| `Tabby-Desktop.dc.html` | `/` รายการหนี้แบบตาราง | เดสก์ท็อป (≥ 900px) |
| `Tabby-Desktop-Form.dc.html` | `/` + modal ฟอร์ม **แก้ไข** (โหมดเพิ่มใช้ modal เดียวกัน หัวข้อ "เพิ่มรายการ" ไม่มีปุ่มลบ) | เดสก์ท็อป |
| `Tabby-Desktop-Test.dc.html` | `/test` | เดสก์ท็อป |

State ที่ **ไม่มีบอร์ด** แต่ต้องทำ (ดูรายละเอียดในหัวข้อ 5): loading (skeleton), error โหลดรายการไม่สำเร็จ, ยืนยันลบบนเดสก์ท็อป, แก้ไขบนมือถือ, ตัวกรองที่ผลว่าง, 422 จาก server, 429

**หมายเหตุ a11y ที่บอร์ดไม่ผ่าน (แก้ตอน implement):**
1. ขอบ input `#D9CBB6` บน `#FFFFFF` ได้ 1.59:1 ต่ำกว่า 3:1 ของ non-text contrast → ใช้ `--border-strong` `#8C7A66` (4.13:1) เป็นขอบ input ปกติ ความหนา 1.5px ตามบอร์ด
2. แถบ progress เติมด้วย `--accent` บนราง `--chip` ได้ 2.5:1 → ใช้ `--accent-ui` `#C2570F`
3. วงกลมติ๊กจ่ายแล้ว: ขอบ/ไอคอน `#8C7A66` บนขาว 4.13:1 ผ่าน แต่บน `--bg` 3.84:1 (ผ่านที่ 3:1) ใช้ได้

## 3. Layout

**Viewport:** `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` และ `<html lang="th">`

**Breakpoint เดียว:** `@media (min-width: 900px)` สลับจากเลย์เอาต์มือถือเป็นเดสก์ท็อป (sidebar + ตาราง) ความกว้างออกแบบมือถือ **390px** ต้องใช้ได้ถึง **360px** (spec ของแอปอื่นกำหนด ≥ 360px; Tabby ใช้เกณฑ์เดียวกัน) ที่ 360px ตัวกรอง segmented ต้องไม่ล้น (label ย่อเป็น "ทั้งหมด 15" ตามบอร์ดอยู่แล้ว) และชื่อ/note ตัดด้วย `text-overflow: ellipsis` ส่วน sidebar ตั้งใจให้ไม่มีช่วง tablet แยก (ที่ 600–899px ใช้มือถือเต็มความกว้าง จำกัด `max-width: 640px` กลางหน้า)

**มือถือ:**
- โครง: header (บนสุด) → การ์ดสรุป → ตัวกรอง → รายการ (scroll ในตัวหน้า ไม่ scroll ซ้อน) → FAB ลอยล่างขวา
- Safe area: `padding-bottom: calc(24px + env(safe-area-inset-bottom))` ให้ FAB และแถบปุ่มล่างของฟอร์ม; รายการมี `padding-bottom: 110px` เพื่อไม่ให้แถวสุดท้ายถูก FAB/toast บัง
- FAB: ขวา 20px ล่าง 24px สูง 56px ข้อความ "เพิ่มรายการ" + ไอคอน + (pill) toast ลอยเหนือ FAB ที่ `bottom: 96px` กว้าง `left/right: 16px` ถ้า FAB กับ toast ซ้อนกันให้ toast อยู่ข้างบนเสมอ
- Header มือถือ: wordmark ซ้าย, ปุ่มไอคอน 44×44 ขวา (ดูช่องว่าง G2)
- หน้าเพิ่ม/แก้ไขและ /test: header เป็นปุ่มย้อนกลับ 44×44 + หัวหน้า ขนาด 22

**เดสก์ท็อป (≥ 900px):**
- Sidebar ซ้าย 232px พื้น `--ink` มีเมนู "รายการหนี้" และ "ทดสอบระบบ" (ปุ่ม 44px สูง, radius 12, active = พื้น `--accent` ตัวหนังสือ `--ink` น้ำหนัก 600, ไม่ active = `--on-dark-2` น้ำหนัก 500) เมนู active ใส่ `aria-current="page"`
- Main: padding 32/40, ไม่จำกัดความกว้างสูงสุด (บอร์ดวาดที่ 1280px) แต่ตั้ง `max-width: 1200px` กันตารางยืดเกินบนจอใหญ่
- **ไม่มี FAB**: ปุ่ม "เพิ่มรายการ" เป็นปุ่ม pill สูง 48 มุมขวาของหัวหน้า
- การทำงานของ modal: เปิดทับเนื้อหา ปิดด้วยปุ่ม ×, ปุ่ม "ยกเลิก", Esc, คลิกฉากหลัง

## 4. Components

ใช้ BEM แบบง่าย (`.block`, `.block__el`, `.is-state`) ทุกปุ่มเป็น `<button type="button">` หรือ `<a>` จริง ไม่มี `div` ที่คลิกได้ ขนาดจุดสัมผัส ≥ 44×44px ทุกตัว

### 4.1 Summary card (การ์ดสรุป)
- มือถือ: การ์ดเดียวพื้น `--ink` radius 24 padding 20 margin `16px 20px 0` มี label 14px `--on-dark-2`, ยอดค้างรวม 40px display, บรรทัดย่อย 14px ("เพื่อน 7 คน ยังไม่จ่าย 10 รายการ" · เมื่อไม่มียอด: "ยังไม่มีใครติดเงิน")

### 4.4 Mark-paid circle button (ปุ่มติ๊กจ่ายแล้ว)
- 44×44 วงกลม ขอบ 1.5px `--border-strong` พื้นขาว ไอคอนถูก 20px (stroke 2) สี `--border-strong`
- states: default (ข้างบน) · hover = พื้น `--chip` · focus = focus ring · pressed/done (`aria-pressed="true"`) = พื้น `--ok-ink` `#1F5B36` ขอบเดียวกัน ไอคอนขาว · busy = ไอคอนหมุนหรือ `aria-busy="true"` และ disabled ชั่วคราว · error = กลับสู่สถานะเดิมและแสดง toast error
- `aria-label` ตามสถานะ: ยังไม่จ่าย → "ทำเครื่องหมายว่า {ชื่อ} จ่ายแล้ว"; จ่ายแล้ว → "ยกเลิกการจ่ายของ {ชื่อ}"
- กดแล้ว: **optimistic update** ส่ง `PUT /api/debts/{id}` ด้วยข้อมูลครบทุกฟิลด์ (spec: Update แทนที่ทั้งแถว) พร้อม `is_paid` สลับค่า ถ้าสำเร็จ แสดง toast (4.5) ถ้าล้มเหลว ย้อนกลับ + toast error

### 4.5 Toast (พร้อมเลิกทำ)
- แถบ `--ink` radius 16 สูงขั้นต่ำ 52 padding `0 8px 0 16px` ตัวหนังสือ `--on-dark` 14px ปุ่ม "เลิกทำ" min-height 44 ตัวหนังสือ `--undo` 600 ไม่มีพื้น
- ข้อความ: "{ชื่อ} จ่ายแล้ว {ยอด}" (เช่น "ต้น จ่ายแล้ว ฿180") เมื่อกดเลิกทำส่ง PUT กลับ (`is_paid` เดิม) แล้วปิด toast
- `role="status"` (aria-live polite) ปิดเองเมื่อครบ **5 วินาที** (ค่าตัวเลขเป็นข้อเสนอ spec ไม่ได้กำหนด) หยุดนับเมื่อ hover/focus อยู่ในตัว toast; toast ใหม่แทนที่ตัวเก่า (ไม่ซ้อนกัน)
- Toast error (ข้อเสนอ): ใช้สไตล์เดียวกัน ข้อความ "ทำรายการไม่สำเร็จ ลองอีกครั้ง" ปุ่ม "ลองใหม่" แทน "เลิกทำ"; กรณี 429 ใช้ "ส่งคำขอถี่เกินไป รอ {retry_after} วินาที" (จาก body `retry_after`)

### 4.15 Histogram (การกระจายเวลาตอบสนอง)

### 4.16 Data table (เดสก์ท็อป)
- ห่อด้วยกล่องขาว radius 20 overflow hidden; `<table>` กว้าง 100% `border-collapse: collapse` 14px; `<caption class="sr-only">รายการหนี้</caption>`

- แถวที่เป็นสถานะจ่ายแล้วเมื่ออยู่ในมุมมอง "ทั้งหมด" ยังคงสไตล์ปกติ (ไม่ขีดฆ่า) ต่างจากมือถือ เพราะมี pill แสดงสถานะอยู่แล้ว
- เรียงตาม `id` จากมากไปน้อยตาม spec (ไม่มีการเรียงตามคอลัมน์ ดังนั้น **ห้ามใส่ลูกศรเรียงในหัวตาราง**)

### 4.17 Pagination
- ข้อความซ้าย "แสดง 1–10 จาก 10 รายการ (หน้าละ 20)" 14 `--ink-2` (`aria-live="polite"`), ขวา: "ก่อนหน้า" | เลขหน้า | "ถัดไป"
- เลขหน้า: ปุ่ม 44×44 radius 12; หน้าปัจจุบัน พื้น `--ink` ตัวหนังสือ `--on-dark` 600 `aria-current="page"`; ก่อนหน้า/ถัดไป สูง 44 padding `0 14px` ถ้าใช้ไม่ได้ = `--border-strong`, `aria-disabled="true"`, ไม่เป็นลิงก์/ปุ่มที่โฟกัสได้ (บอร์ดวาดเป็น span); ถ้ามีหลายหน้าให้ย่อด้วย "…" (แสดง 1, ปัจจุบัน±1, สุดท้าย)
- `per_page` คงที่ 20 (spec: ค่าเริ่มต้น 20, สูงสุด 100) ไม่มีตัวเลือกให้ผู้ใช้เปลี่ยน
- มือถือ: ไม่มีบอร์ด → ใช้ตัวควบคุมเดียวกันแบบย่อที่ท้ายรายการ (ข้อความ "หน้า 1 จาก 3" + "ก่อนหน้า"/"ถัดไป" ปุ่ม 44px) ไม่ใช้ infinite scroll (spec ไม่ได้กำหนด และจะกระทบการวัด API)

### 4.18 Modal (เดสก์ท็อป)
- ฉากหลัง `--scrim` เต็มพื้นที่ + กล่องกึ่งกลาง `max-width: 460px` padding 32 radius 28 พื้นขาว เงา `--shadow-modal`
- หัวแถว: `<h2>` "แก้ไขรายการ" / "เพิ่มรายการ" 22/600 + ปุ่ม × 44×44 (`aria-label="ปิด"`, margin-right -12) → ฟอร์ม label+input ระยะห่างระหว่างช่อง 20 → แถวปุ่ม margin-top 28: "บันทึก" (flex 1 สูง 52 พื้น `--accent`) + "ยกเลิก" (สูง 52 padding `0 24px` พื้น `--chip`) → ปุ่มข้อความ "ลบรายการนี้" (เฉพาะโหมดแก้ไข width 100% สูง ≥ 44 `--danger` 14/600 margin-top 12) ที่กดแล้วเปิด dialog ยืนยัน (4.7 แบบกลางจอ) ซ้อนทับ
- a11y: `role="dialog" aria-modal="true"`, โฟกัสแรกที่ช่อง "ใครยืม", ดักโฟกัส, Esc ปิด (ถ้ามีข้อมูลที่แก้แล้วไม่ถาม ยกเลิกทันที — ข้อมูลน้อย), คืนโฟกัสให้ปุ่ม "แก้ไข" ของแถว

## 5. Screen by screen

ข้อมูลทุกหน้าได้จาก API ตาม spec หัวข้อ 5: `GET /api/debts?page=&per_page=20&paid=`, `POST /api/debts` (201), `PUT /api/debts/{id}` (200), `DELETE /api/debts/{id}` (204), `GET /api/summary`; ฟิลด์แถว: `id, friend_name, amount (string "150.00"), note (nullable), is_paid (0|1), created_at, updated_at (UTC ISO 8601)` รูปแบบ envelope ของ list/summary ให้ยึดตัวอย่าง JSON ในหัวข้อ 5 ของ spec (เอกสารนี้ไม่ระบุชื่อ field ของ envelope เพื่อไม่ให้ขัดกัน)

> ข้อควรรู้: ต้องการตัวเลข "จำนวนทั้งหมด/ยังไม่จ่าย/จ่ายแล้ว", "จำนวนเพื่อนที่ติดเงิน", "จำนวนรายการค้างจ่าย", "ยอดค้างรวม" ให้ใช้จาก `/api/summary` ถ้า spec ปัจจุบันไม่มีครบทุกฟิลด์เหล่านี้ ให้ **แก้ spec และทุก stack ให้ตรงกัน** (ห้ามเพิ่ม field เฉพาะ stack ใด stack หนึ่ง) ก่อน implement หน้าจอ

### 5.1 `Main` — / (มือถือ)
- **จุดประสงค์:** ดูรายการหนี้ทั้งหมด กรอง ติ๊กจ่ายแล้ว
- **ส่วนต่างๆ บนลงล่าง:** header (wordmark "Tabby" + ปุ่มไอคอน 44px ดูช่องว่าง G2) → การ์ดสรุป (4.1) → segmented (4.2, ค่าเริ่มต้น "ทั้งหมด") → กลุ่มรายการ (4.3) → controls หน้า (4.17) → FAB "เพิ่มรายการ" (4.6) → toast (4.5, เมื่อมีเหตุการณ์)
- **Interaction:** แตะแถว = ไปแก้ไข (`#/edit/{id}`); ปุ่มติ๊ก = สลับจ่ายแล้ว + toast เลิกทำ; เปลี่ยนตัวกรอง = โหลดหน้า 1 ใหม่ ไม่ reload เพจ
- **Loading:** การ์ดสรุป + 5 แถว skeleton (avatar วงกลม, 2 แถบข้อความ, แถบจำนวน สี `--chip` ไม่มี shimmer เมื่อ reduced motion) `aria-busy="true"` บน `<main>`
- **Error:** โหลดไม่สำเร็จ → กล่องในที่ของรายการ: "โหลดรายการไม่สำเร็จ" + ปุ่ม "ลองใหม่" (ข้อเสนอ); 429 แสดง retry_after
- **Empty:** ดู 5.4
- **Test hooks (ข้อเสนอ):** `data-testid`: `summary-total`, `summary-sub`, `filter-all|unpaid|paid`, `debt-row` (+ `data-id`), `debt-name`, `debt-amount`, `check-btn`, `fab-add`, `toast`, `toast-undo`, `pager-prev|next`

### 5.2 `Tabby-Add` — /#/new (และ /#/edit/{id}) มือถือ
- **จุดประสงค์:** เพิ่มหรือแก้ไขหนี้ทีละรายการ
- **ส่วน:** header [← ย้อนกลับ (ลิงก์ไป `#/` `aria-label="กลับไปรายการหนี้"`) + h1 "เพิ่มรายการ" (แก้ไข: "แก้ไขรายการ")] → ช่อง "ใครยืม" (ค่าเริ่มต้นว่าง; บอร์ดใส่ "ต้น" เป็นตัวอย่าง) + chip ชื่อเพื่อน → ช่อง "จำนวนเงิน (บาท)" (placeholder "0", 28px) + chip "+50 / +100 / +500 / +1000" → ช่อง "โน้ต (ไม่ใส่ก็ได้)" placeholder "เช่น ค่าข้าวเที่ยง" → แถบล่างติดขอบ: "บันทึก" (สูง 56 pill พื้น `--accent`) และลิงก์ "ยกเลิก" (สูง ≥ 44 กลาง `--ink-2` 14/500) → (โหมดแก้ไขเท่านั้น) ปุ่มข้อความ "ลบรายการนี้" สีแดง เหนือปุ่มบันทึก (ข้อเสนอ ดูช่องว่าง G3)
- **ส่ง:** `POST /api/debts` (เพิ่ม) / `PUT /api/debts/{id}` (แก้ ส่งฟิลด์ทั้งหมด รวม `is_paid` เดิม); `amount` ส่งเป็นทศนิยมไม่เกิน 2 ตำแหน่ง; ตัดช่องว่างหัวท้ายชื่อก่อนส่ง
- **State:** busy (ปุ่ม "กำลังบันทึก…" disabled), error client/422 (ดู 4.8; บอร์ดแสดง error ที่ช่องจำนวนเงิน), สำเร็จ = กลับ `#/` โหลดรายการหน้า 1 และเลื่อนไปบนสุด แล้วไฮไลต์แถวใหม่สั้นๆ (`--row-hl` 1.5 วินาที) พร้อม toast "เพิ่มรายการของ{ชื่อ}แล้ว" (ข้อเสนอ)
- **กดย้อนกลับของ browser** ต้องกลับ `#/` (ใช้ hash history ปกติ)
- **Test hooks:** `input-friend`, `input-amount`, `input-note`, `error-friend|amount|note`, `btn-save`, `btn-cancel`

### 5.3 `Tabby-Delete` — dialog ลบ (มือถือ)
- ฉากหลังคือรายการวันนี้ (หัวสรุปยอด + กลุ่ม "วันนี้" พร้อมแถวเป้าหมายไฮไลต์ `--row-hl`) ไม่มีตัวกรอง/FAB (ถูกฉากหลังบัง)
- แผ่น 4.7: "ลบรายการของแพรว?" / "ค่าแท็กซี่กลับบ้าน ฿280 จะหายไปจากสมุด และกู้คืนไม่ได้" / [ลบรายการ] [ยกเลิก]

### 5.5 `Tabby-Test` — /test (มือถือ)
- header: ← (ลิงก์ `/`) + h1 "ทดสอบระบบ" (22/600) → การ์ด 3 ใบเรียงแนวตั้ง ในโซน scroll
- **ช่องกรอก token (ไม่มีในบอร์ด, spec หัวข้อ 12 บังคับ):** การ์ดเล็กแรกสุด หัว "รหัสทดสอบ" ช่อง `type="password"` label "X-Test-Token" ข้อความช่วย "ใช้กับ download, upload, slow, seed และล้างแคช เก็บไว้ในหน้านี้เท่านั้น ปิดหน้าแล้วหาย" (ข้อเสนอคำอธิบาย) เก็บใน **ตัวแปรในหน่วยความจำเท่านั้น** ห้าม localStorage/cookie ถ้าไม่มี token แล้วกดเครื่องมือที่ต้องใช้ → แสดง error ใต้ปุ่ม "ใส่รหัสทดสอบก่อน" (server ตอบ 403 `{"error":"forbidden"}` ให้แสดงข้อความเดียวกัน)
- **Bandwidth:** select "ขนาดไฟล์ดาวน์โหลด" ตัวเลือก **1 MB, 10 MB, 100 MB** (spec; บอร์ดวาด 1/10/50 ให้ใช้ spec) ค่าเริ่มต้น 10 MB → meter (4.12) → ปุ่ม "เริ่มดาวน์โหลด" + "ทดสอบอัปโหลด" (อัปโหลดใช้ขนาดเดียวกับที่เลือก: ไฟล์สุ่มสร้างฝั่ง browser) → ปุ่มรองเต็มความกว้าง "5 พร้อมกัน" (ดาวน์โหลด 10 MB พร้อมกัน 5 connection ตาม spec; ข้อเสนอตำแหน่ง) → ผลรวมของ 5 connection แสดงในแถวผลเดียวกัน (Mbps รวม)
  - `GET /download/{mb}` (mb ∈ 1,10,100), `POST /upload` (multipart ช่อง `file`), รันขนาดละ 3 รอบ แสดงมัธยฐาน, ต้องแนบ header `X-Test-Token`
  - states: running = ปุ่มทั้งกลุ่ม disabled, ปุ่มที่กดเปลี่ยนข้อความ "กำลังทดสอบ…", `aria-busy` บนการ์ด; ยกเลิกกลางคันไม่มีใน spec (ไม่ต้องทำ); 413 ตอนอัปโหลด → badge/ข้อความ "ขนาดใหญ่สุดที่ผ่าน: n MB" (spec: ให้จดขนาดที่ผ่านล่าสุด) ; error เครือข่าย → ข้อความ error ใต้ปุ่ม
- **Caching:** รายการตรวจ (4.13) ตาม spec หัวข้อ 7 ทั้ง 7 ข้อ ใช้ชื่อแถว: "ETag" (1/2 รวมกับ detail), "Cache-Control", "ส่งซ้ำด้วย If-None-Match" (ข้อ 2), "no-store (/cache/none)" (ข้อ 3), "แคชฝั่ง server (/cache/time)" (ข้อ 4 → badge "บันทึก"), "บีบอัด (/cache/gzip)" (ข้อ 5), "App cache (/api/summary)" (ข้อ 6 MISS→HIT→MISS), "ไฟล์ static (CSS/JS)" (ข้อ 7 → ผ่านเมื่อมี ETag หรือ Last-Modified, detail แสดง Cache-Control ที่ได้ หรือ "ไม่มี Expires หรือ max-age") ปุ่ม "ตรวจใหม่" รันตามลำดับ และข้อที่ spec ให้ตรวจ "ใน DevTools" (ข้อ 1) ให้แสดง detail "เปิด /cache/static ซ้ำใน DevTools" พร้อมลิงก์ `target=_blank rel=noopener` ถ้าจะตรวจอัตโนมัติด้วย `PerformanceResourceTiming.transferSize === 0` ให้ระบุว่าเป็นค่าประมาณ
  - ข้อ 6 (App cache) ต้องสร้างแถวใหม่ระหว่างตรวจ spec: MISS → HIT → สร้างแถว → MISS ให้ใช้ `POST /api/debts` แล้ว `DELETE` แถวนั้นทิ้งเองทันทีหลังตรวจ และแจ้งผู้ใช้ใต้ปุ่ม "ตรวจใหม่" ว่าการตรวจนี้เขียน/ลบข้อมูลชั่วคราว 1 แถว (ข้อเสนอการจัดการ; spec ไม่ได้ระบุว่าแถวมาจากไหน)
  - ปุ่ม "ล้างแคชแอป" (`DELETE /api/cache` ต้อง token) เป็นปุ่มรองข้างปุ่ม "ตรวจใหม่" และแสดง hit/miss จาก `GET /api/cache-stats` (ข้อเสนอ ตามที่ spec มี endpoint)
- **API Request:** select endpoint เป้าหมาย 6 ตัวตาม spec (`/api/ping`, `/api/ping?db=1`, `/api/debts?page=1`, `/api/summary`, `/api/slow?ms=200`, `/api/limited`) — **ไม่มีในบอร์ด** ต้องเพิ่มไว้เหนือช่องจำนวนคำขอ; ช่อง "จำนวนคำขอ" (ค่าเริ่มต้น 100, สูงสุด 1,000; บอร์ดแสดง 200 เป็นตัวอย่าง) กับ "พร้อมกัน" (ค่าเริ่มต้น 10, สูงสุด 50) เรียงแถวเดียว 2 คอลัมน์; ปุ่ม "เริ่มทดสอบ" เต็มความกว้าง; ผล = stat tiles (4.14) + histogram (4.15)
  - เกินเพดาน = จำกัดค่าและแสดง error ใต้ช่อง "สูงสุด 1,000" / "สูงสุด 50"; `/api/slow` ต้องมี token
  - running: ปุ่ม "กำลังทดสอบ… (n/N)" disabled; แถบความคืบหน้าบางๆ ใต้ปุ่มใช้ `role=progressbar` (ข้อเสนอ)
  - ผลใช้ค่า latency ที่วัดฝั่ง client + `Server-Timing: app;dur=` จาก response; p95 = ลำดับที่ `ceil(0.95 × N)` หลังเรียงน้อยไปมาก (ตาม spec)
- **Test hooks:** `token-input`, `bw-size`, `bw-start-dl`, `bw-start-ul`, `bw-start-5x`, `bw-speed`, `bw-progress`, `cache-run`, `cache-row-{key}`, `api-endpoint`, `api-reqs`, `api-conc`, `api-run`, `api-stat-{avg|median|p95|max|rps|err|ok|server}`, `api-histogram`

## 6. Flows

**F1 เพิ่มรายการ (มือถือ):** แตะ FAB → `#/new` → กรอกชื่อ (หรือแตะ chip ชื่อ) → จำนวนเงิน (พิมพ์หรือแตะ chip "+100") → โน้ต (ไม่บังคับ) → "บันทึก" → ตรวจ client → `POST /api/debts` → 201 → กลับ `#/` รายการหน้า 1 ตัวกรอง "ทั้งหมด" แถวใหม่ไฮไลต์ + สรุปอัปเดต → ถ้า 422 ค้างในฟอร์ม พร้อม error ใต้ช่อง และโฟกัสช่องแรกที่ผิด
**F1d (เดสก์ท็อป):** "เพิ่มรายการ" → modal → ขั้นตอนเดียวกัน → สำเร็จ = ปิด modal + แถวใหม่ไฮไลต์

**F2 ติ๊กจ่ายแล้ว + เลิกทำ:** แตะปุ่มติ๊ก → ปุ่มและแถวเปลี่ยนสถานะทันที (optimistic) → ส่ง `PUT` ครบฟิลด์ `is_paid` สลับ → สำเร็จ: toast "{ชื่อ} จ่ายแล้ว {ยอด}" + "เลิกทำ" (5 วิ) + ตัวนับตัวกรองและสรุปยอดอัปเดต; ถ้าเปิดตัวกรอง "ยังไม่จ่าย" แถวหายไปจากรายการหลัง toast ปรากฏ (ควรหายแบบเลื่อนเข้า 150ms หรือหายทันทีเมื่อ reduced motion) → "เลิกทำ" = `PUT` กลับ และแถวกลับมา; ล้มเหลว = ย้อนกลับ + toast error

**F3 ลบ:** แก้ไข (มือถือ) / ปุ่ม "ลบ" (เดสก์ท็อป) → dialog ยืนยัน (โฟกัสที่ "ยกเลิก") → "ลบรายการ" → `DELETE` 204 → ปิด dialog/กลับ `#/` ลบแถว อัปเดตสรุป ถ้าหน้านั้นว่างหลังลบและไม่ใช่หน้า 1 ให้ถอยไปหน้าก่อนหน้า → toast "ลบรายการของ{ชื่อ}แล้ว"

**F4 กรอง + แบ่งหน้า:** แตะตัวกรอง → `aria-pressed` อัปเดต → เรียก `GET /api/debts?page=1&per_page=20[&paid=0|1]` → แสดงผล, "แสดง 1–N จาก M" (เดสก์ท็อป) → ก่อนหน้า/ถัดไป/เลขหน้า เปลี่ยน `page` และเลื่อนไปบนสุดของรายการ ผลว่าง = ข้อความ 4.10 (กรณีตัวกรอง)

**F5 Bandwidth:** ใส่ token → เลือกขนาด → "เริ่มดาวน์โหลด" → 3 รอบ (progress + "รอบที่ n/3") → แสดงมัธยฐาน Mbps, TTFB, เวลารวม → "ทดสอบอัปโหลด" ได้ผลแบบเดียวกัน → "5 พร้อมกัน" ได้ Mbps รวม → 403 = ขอ token, 413 = บอกขนาดใหญ่สุดที่ผ่าน

**F6 Caching:** "ตรวจใหม่" → แถวทั้งหมดเป็น "กำลังตรวจ…" → ผลทีละแถวตามลำดับ (ผ่าน/ไม่ผ่าน/บันทึก) → สรุปเป็นข้อความ `aria-live="polite"` "ผ่าน 5 จาก 7 ข้อ"

**F7 API load test:** เลือก endpoint → กำหนดจำนวน/พร้อมกัน (ถูกจำกัดที่ 1,000/50) → "เริ่มทดสอบ" → แสดงความคืบหน้า → ผล stat tiles + histogram + รายการ error ตาม status → รันซ้ำได้ (ผลเก่าถูกแทนที่)

## 9. Implementation checklist สำหรับ Claude Code

**ไฟล์ที่ต้องสร้าง (ชุดเดียวใช้ร่วมกันทั้ง 4 stack):**
- `public/index.html` — โครงหน้า `/` (header, summary, filter, list/table, dialogs ว่างๆ ที่ JS เติม) ไม่มี logic เฉพาะ stack
- `public/test.html` — โครงหน้า `/test`
- `public/static/css/tabby.css` — token (2.4) + layout + components ทั้งหมดตามหัวข้อ 3–4 (หนึ่งไฟล์ ไม่มี build)
- `public/static/js/app.js` — logic หน้า `/` (state, fetch wrapper, render, hash router, dialogs, toast)
- `public/static/js/test.js` — logic หน้า `/test` (bandwidth, caching, load test)
- `public/static/fonts/*.woff2` — ฟอนต์ self-host
- ไม่ต้องมี template engine ในฝั่ง server: server ส่งไฟล์ static ตรงๆ (Apache/Nginx ตั้ง `DirectoryIndex`/`try_files`; Node ใช้ `express.static`; Flask ใช้ `send_from_directory`) เพื่อให้หน้าเว็บเหมือนกันทุก stack

**กติกาโค้ด:**
1. สร้าง DOM ด้วย `textContent`/`createElement` หรือ escape ทุกค่าก่อน `innerHTML` (spec: escape ทุกช่อง กัน XSS) ห้ามใส่ `friend_name`/`note` ผ่าน `innerHTML`
2. `fetch` wrapper เดียว: same-origin (ไม่ใช้ CORS), ใส่ `X-Test-Token` เฉพาะ endpoint ที่ spec หัวข้อ 12 ระบุ, อ่าน `retry_after` ตอน 429, แปลง 422 เป็น error ต่อช่อง, ไม่ log token
3. เงิน: เก็บเป็น string จาก API; ทำเลขเพิ่มจาก chip ด้วย integer สตางค์ แล้วแปลงกลับ ห้ามใช้ float บวกยอดรวมเอง
4. เวลา: แสดงผลตาม `Asia/Bangkok` ปี พ.ศ.; ข้อมูล API เป็น UTC
5. Hash router เล็กๆ (`#/`, `#/new`, `#/edit/:id`) ตั้งโฟกัสทุกครั้งที่เปลี่ยน view (ไปที่ `<h1>` ของ view ใหม่ มี `tabindex="-1"`)
6. ไม่มี dependency ภายนอก (ไม่มี CDN, ไม่มี framework)

**ลำดับงาน:**
1. `tabby.css` ส่วน token + reset + layout shell (มือถือก่อน แล้ว media query 900px)
2. หน้า `/` มือถือ: summary, segmented, รายการ, FAB, empty, skeleton, error (ต่อ mock JSON ก่อนจนกว่า API พร้อม แล้วสลับเป็น `fetch` จริง)
3. ฟอร์มเพิ่ม/แก้ไข + chip + validation + 422
4. ติ๊กจ่ายแล้ว + toast เลิกทำ; dialog ลบ (sheet)
5. เดสก์ท็อป: sidebar, การ์ดสรุป 3 ใบ, ตาราง, pagination, modal, dialog กลางจอ
6. `/test` มือถือ → เดสก์ท็อป: token, Bandwidth, Caching 7 ข้อ, Load test + histogram
7. ตรวจตามรายการด้านล่าง แล้วทดสอบกับ API จริงของแต่ละ stack ผ่านหน้าเว็บเดิมโดยไม่แก้ไฟล์ front-end

**เกณฑ์ตรวจรับ:**
- [ ] Contrast ตัวหนังสือ ≥ 4.5:1 และ UI/ขอบ ≥ 3:1 ทุกคู่สีที่ใช้ (ใช้ตารางในหัวข้อ 2.1 และตรวจซ้ำด้วยเครื่องมือ)
- [ ] จุดสัมผัสทุกตัว ≥ 44×44px (ปุ่มติ๊ก, ปุ่มตาราง, chip, เลขหน้า, ปุ่มปิด ×)
- [ ] ใช้คีย์บอร์ดทำได้ครบทุก flow F1–F7: Tab ตามลำดับสมเหตุสมผล, Enter/Space กดปุ่ม, Esc ปิด dialog/modal, โฟกัสถูกดักและคืนค่า, focus ring เห็นชัดบนพื้นสว่างและพื้นเข้ม
- [ ] Screen reader: ทุก input มี label, error ผูก `aria-describedby`, ตัวกรองบอกสถานะ `aria-pressed`, toast/สรุปผลอยู่ใน live region, กราฟ/progress มีข้อความทางเลือก, `aria-current` บน nav/หน้า/เมนู
- [ ] ไม่พึ่งสีอย่างเดียว (badge มีข้อความ, error มีข้อความ+ขอบหนาขึ้น)
- [ ] ไม่มี horizontal scroll ที่ 360px และ 1280px; ใช้งานได้ที่ 200% zoom
- [ ] `prefers-reduced-motion` ปิด transition/animation
- [ ] ไม่มี request ออกนอก origin (เช็ก Network ว่าไม่มี Google Fonts)
- [ ] `/static/css`, `/static/js`, ฟอนต์ มี `ETag` หรือ `Last-Modified` (บันทึก `Cache-Control` ที่ server ให้) — เป็นข้อ 7 ของรายการตรวจ caching ใน spec
- [ ] ผล UI ตรงกันทั้ง 4 stack (ไฟล์ static byte-for-byte เดียวกัน)
- [ ] ปุ่ม/ฟีเจอร์ที่ตัดออกตาม G1 ไม่ปรากฏใน DOM
- [ ] ไม่มี sample data (ชื่อ/ยอดตัวอย่างจากบอร์ด) หลงเหลือในโค้ด
